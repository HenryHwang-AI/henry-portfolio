Operations daily active use. It stays “90%+”, not 90%. The resume does not define the denominator or the comparison base.

原报表有 50+ 个指标。运营的说法是看不过来，看了也不知道做什么。调研了 4 个部门、40 位资深运营之后，痛点被定在「指标 → 动作」中间缺一层翻译，而不是再缺一个取数窗口。

先做翻译层，而不是再加一张更宽的表

执行落地的是能自然语言问数、也能主动提醒的经营分析 Copilot。数据分析定义成三段：健康度评分，用 8 个核心指标；异常归因，自动找拖分项；然后是动作建议。

让回答能被相信的基础有两件。一是《运营经营指标体系白皮书 V1.0》，把散在 5 个系统里的 200+ 指标口径收成一把尺子，同时给可信回答和效果评测用。二是推动数据侧沉淀 8 张 ADS 表并建立血缘，让结论可追溯、评测可复盘。核心指标是 8 个，不改成别的个数。

三个让它能被天天用的决定

结构按「好不好、为什么、做什么」，不按报表字段。健康度只留 8 个核心指标，归因去找拖分项，再给动作。

先统一口径，再让模型说话。白皮书是那把尺子。

用主题域、ADS 表和血缘支撑可追溯。没有这层，自然语言问数和自动归因很难复核。简历没有写具体算法名称，这里也不补。

结果

经营日报和周报由模型自动生成，支持自然语言问数。异常归因准确率 95%+，简历没有对照基线。运营使用日活 31% → 90%+。运营业务流程耗时减少 70%。落地范围是全公司 1000+ 运营人员，并成为经营数据分析的核心工具。

简历没有版本表。后面的客服 RAG 和 Agent 是否沿用了「先翻译再行动」，简历也没有写，不能当成事实。

The old reports carried 50+ metrics. Operators could not get through them, and reading them still did not say what to do. After interviews with 40 senior operators across 4 departments, the pain was defined as a missing translation from metric to action, not as a missing query box.

Build the translation layer before widening the table

The work executed was an operations Copilot that answers questions in natural language and can raise a reminder. Analysis is three parts: a health score on 8 core metrics, an automatic trace to the item dragging the score down, and a suggested action.

Two pieces make an answer believable. One is the operations metrics white paper, V1.0, which gathers 200+ metric definitions scattered across 5 systems into one ruler for both answers and evaluation. The other is 8 ADS tables with lineage, so a conclusion can be traced and an evaluation can be replayed. The core set is 8 metrics. It is not rewritten as some other count.

Three decisions that made it a daily tool

Structure the product as “how is it, why, what next,” not as report fields. Health keeps 8 core metrics, attribution finds what drags the score, then comes an action.

Unify definitions before the model speaks. The white paper is that ruler.

Use subject areas, ADS tables, and lineage so a conclusion can be checked. Without that layer, natural-language questions and automatic attribution are hard to review. The resume does not name an algorithm, and this page does not add one.

Outcomes

Daily and weekly operating reports are generated by the model, with natural-language questions. Anomaly-attribution accuracy is 95%+; the resume gives no baseline. Operations daily active use went from 31% to 90%+. Operating-process time fell 70%. The rollout was 1,000+ operators across the company, and it became the core tool for operating analysis.

The resume has no version table. It also does not say that the later support RAG or the agents inherited “translate, then act.” That is not stated as fact.
