商舟｜选品测款 AgentShangzhou · selection and test Agent

4h → 0.5h

同等商品规模下的单次选品耗时，降幅 87.5%。这不是一键刊登：利润、合规和 Listing 等关键节点仍由人确认。简历另记人工操作 100+ 次 → 9 次，并写人工投入时长 ↓90%。两则并陈，计算细节未载。

Time for one selection pass at the same catalog scale, down 87.5%. This is not one-click listing: profit, compliance, and listing still stop for a person. The resume also records manual operations 100+ → 9, and a 90% drop in manual time. Both statements stand; the calculation detail is not given.

批量选品的材料是散的，判断靠个人经验，标准也不统一，所以周期长，同一结论很难再跑一遍。缺的不是再多一个分析页，而是一条能执行、又能把结论追回数据和规则的流程。

一条可追溯的链路，而不是把经验交给黑盒

我作为 AI 产品负责人主导这条产品：用 Workflow 把「采集 → 筛选 → 利润与合规评估 → Listing 生成 → 刊登」串起来。Agent 用 Function Calling 取数和分析，多模态模型生成商品图片和视频素材，知识库约束分析和生成。自动执行，结论可追溯，只在关键节点留 Human-in-the-loop。

方案和原型按九步选品流程来做。节点按确定性和风险分成三类：Workflow、Agent 决策、人工确认。利润和合规评估放在前面，而不是刊登失败后再补。Agent Loop 写成：自动筛选 → Tool Calling 取数 → AI 分析 → 人工确认 → Listing 生成 → 上架。

三个让流程能被采用、结论能被复核的决定

按风险分权，而不是全流程自动化。先拆痛点、场景和优先级，再规定哪一步走流程、哪一步交给 Agent、哪一步必须人点头。这是产品边界，不是上线后的补丁。

报告和 Listing 分开做分层 Eval。Badcase 归因到 Prompt、规则、Tool 或数据源，回灌后再回归。简历所载：选品报告人工复核通过率 95%+，关键结论数据可追溯率 99%。

按步骤取数，节点之间只传结构化中间结果。Context 只留当步商品和命中规则，用来压 Token 成本和延迟。简历没有给出成本或延迟数字。知识库沉淀利润口径、合规规则和历史结论，按步骤检索，结论回到数据和规则条款，目标包括降低刊登驳回风险。驳回率的前后数字，简历没有写。

结果

同等商品规模下，单次选品 4 小时 → 0.5 小时（↓87.5%）；人工操作 100+ 次 → 9 次，人工投入时长 ↓90%。复核通过率 95%+，可追溯率 99%。「自动筛选 → AI 分析 → 人工确认」被多个运营团队采用，累计 3000+ 次选品任务，并成为公司标准选品流程。「多个」没有给出团队数。

非数字的部分是这条标准流程、分层 Eval 和按步骤回溯的知识库。商业化在简历里是「构建、规划」，没有可写的收入结果。协同研发完成了开发和上线，并按验收和用户反馈迭代。简历没有分版月份，这里不排时间表。

Selection material was scattered, judgment sat with individual experience, and the criteria were not shared. Cycles were long, and the same conclusion was hard to run again. The missing piece was not another analysis screen. It was a path that can execute, and that can trace a conclusion back to data and rules.

A traceable path, not a black box for experience

As AI product lead I owned the product definition: a workflow from collect, to filter, to profit and compliance review, to listing generation, to publish. The agent fetches and analyzes through function calling. A multimodal model produces product images and video. A knowledge base constrains both analysis and generation. Execution is automatic, conclusions are traceable, and a person stays only at the critical nodes.

The plan and prototype follow a nine-step selection flow. Nodes are split by certainty and risk into workflow steps, agent decisions, and human confirmations. Profit and compliance sit up front, not after a listing is rejected. The loop is: auto-filter, tool calling, AI analysis, human confirm, listing generation, publish.

Three decisions that made the flow adoptable and reviewable

Split authority by risk, instead of automating the whole path. Name the pain, the scenario, and the priority first. Then decide which step is a workflow, which step an agent may decide, and which step needs a person. That boundary is the product, not a patch after launch.

Evaluate the report and the listing in layers. A bad case is traced to the prompt, the rule, the tool, or the data source, then fed back and regression-tested. Resume-reported: human review pass rate on selection reports 95%+, and traceability of key conclusions 99%.

Fetch data per step, and pass only a structured intermediate result. Context keeps the current item and the rules that hit, to hold down token cost and latency. The resume gives no cost or latency figure. The knowledge base holds profit definitions, compliance rules, and past conclusions, retrieved per step, so a conclusion can return to the data and the clause. One aim is a lower listing-rejection risk. The resume does not give a before-and-after rejection rate.

Outcomes

At the same catalog scale, one selection pass went from 4 hours to 0.5 hours (down 87.5%). Manual operations went from 100+ to 9, with manual time down 90%. Review pass rate 95%+. Traceability 99%. The standard path — auto-filter, AI analysis, human confirm — was adopted by multiple operations teams, completed 3,000+ selection tasks, and became the company’s standard selection process. “Multiple” is not a headcount.

What is not a number: that standard process, the layered evaluation, and a knowledge base that can be walked step by step. Commercialization is described as building and planning a path. There is no revenue result to report. Engineering shipped it, and later changes followed acceptance and user feedback. The resume has no version calendar, so this page does not invent one.
