API 优先、GUI 兜底：我搭 Agent 时的集成原则 API first, GUI fallback: my integration rule for agents

做投放作战室、评测台和引溯时，我反复遇到同一个分叉：Agent 是去点界面，还是去调接口？默认答案我写死了——API 优先，GUI 只做兜底。这条原则看起来土，却决定了后面所有分层能不能站得住。

为什么

GUI 自动化脆：布局一变就碎，难回放，也难进评测。API 有契约、有错误码、能重试，适合作为工具层的稳定面。三个 Demo 共用「场景 Bot + 工具层」时，如果工具层漂在截图点击上，分层就只是故事，评测台也对不齐同一条路径。

更现实的一点：广告与文档系统往往已有正式 API。放着不用，却去教 Agent「看屏幕」，是在用高方差手段解决低方差问题。

怎么落地

协调 Bot 只下达意图；场景 Bot 选择工具；工具层先查有没有正式 API / SDK。没有接口、又必须完成的步骤，才允许 GUI 路径，并且把它标成「脆弱依赖」——评测里单独记一笔，提醒自己尽快换掉。权限、配额、审计日志也只挂在 API 路径上，GUI 逃生舱默认不进生产主链路。

我学到什么

「能自动化」不等于「该自动化成主路径」。主路径要可测、可版本化；GUI 是逃生舱，不是高速公路。这一条让我在加新场景时少写很多事后补丁，也让多 Agent 协作有了共同的地面，而不是各自发明一套点击脚本。工具层一旦稳定，作战室换角色、评测台加用例，都不必重写集成。

Building the war room, eval lab, and citation advisor, I kept hitting the same fork: should the agent click a UI or call an API? I hardcoded the default—API first, GUI only as fallback. It sounds plain, but it decides whether the layering story can stand.

Why

GUI automation is brittle: layouts break it, replays hurt, and evals get noisy. APIs give contracts, error codes, and retries—a stable tools surface. If three demos share scene bots plus a tools layer, floating that layer on screenshot clicks turns “layering” into fiction and misaligns the eval lab.

Practically, ads and document systems already expose real APIs. Ignoring them to teach an agent to “look at the screen” is high-variance work on a low-variance problem.

How I apply it

The coordinator states intent; scene bots pick tools; the tools layer checks for a real API/SDK first. Only when there is no interface and the step is mandatory do I allow a GUI path—and I label it a fragile dependency, scored separately in eval so I remember to replace it. Auth, quotas, and audit logs ride the API path; the GUI hatch stays out of the production mainline by default.

What I learned

“Can automate” is not “should be the main path.” The main path must be testable and versionable; GUI is an escape hatch, not a highway. That rule saves after-the-fact patches when I add scenes, and gives multi-agent collaboration shared ground instead of competing click scripts.
