广告 Agent 评测台：怎么量「好不好用」 Eval lab: measuring whether an ads agent is actually usable

Agent 演示都好看，难的是上线前敢不敢说「过线了」。我建广告 Agent 评测台，是为了把「感觉不错」换成可重复的用例和分数。没有分数，作战室和引溯都只是体验很好的 Demo。

为什么先写用例

广告 Agent 的失败很具体：预算建议离谱、忽略硬约束、把诊断写成鸡汤。这些用自由对话很难抓；用固定用例——输入、期望行为、打分维度——才能横向对比版本和基线。我甚至会写「必须拒绝」的用例：该说不知道、该要求补充字段时，瞎答就算挂。

用例比模型版本更保值。模型换了，用例还在；提示词改了，回归一眼能看出来。

评测台怎么跑

思路很朴素：用例集 → 跑 Agent → 对照基线打分 → 看回归。分数可以粗糙，但必须公开维度：正确性、约束遵守、可执行性。和作战室、引溯共用「API 优先」工具层时，评测也能打到同一套接口上，而不是只评聊天语气。

我学到什么

没有评测台，多 Agent 只是舞台剧。有了它，你才知道哪次提示词改动是进步，哪次只是换了说法。先写用例再谈上线——这句话比任何新模型发布都管用。评测台本身也是产品：它逼你把「好」定义清楚，否则分数无从下笔。我现在每加一个场景 Bot，第一件事不是写演示脚本，而是先丢三条硬用例进台子。

Demo：ad-agent-eval-lab · GitHub：仓库

Agent demos always look sharp. The hard part is saying “this clears the bar” before you ship. The Ad Agent Eval Lab exists to replace vibes with repeatable cases and scores. Without scores, the war room and citation advisor remain pleasant demos.

Write cases first

Ads-agent failures are concrete: wild budget advice, ignored hard constraints, diagnosis that reads like a pep talk. Free chat rarely catches them. Fixed cases—input, expected behavior, scoring axes—let you compare versions and baselines. I also write “must refuse” cases: if the agent should ask for missing fields or admit uncertainty, guessing is a fail.

Cases outlive model versions. Swap the model, keep the suite; change a prompt, see the regression.

How the lab runs

Case set → run agent → score against a baseline → watch regressions. Scores can be coarse if the axes are public: correctness, constraint obedience, actionability. Sharing an API-first tools layer with the war room and citation RAG means evals hit the same interfaces, not just chat tone.

What I learned

Without an eval lab, multi-agent work is theater. With it, you know which prompt change moved the needle and which only changed the wording. Cases before ship beats any model launch day. The lab is also a product: it forces you to define “good,” or you cannot score at all.
